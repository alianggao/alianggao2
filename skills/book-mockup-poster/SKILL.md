# 自营店图书生成任务规范

## 用途

把一张图书封面照片，套用已验收的电商主图版式，输出 1520×1520 与 760×760 两个尺寸的上架图。

两张图默认都控制在 **1 MB 以内**（电商后台上传普遍卡 1MB/张）。脚本先尝试无损编码，撑不住上限才逐档降为调色板，取"能塞进 1MB 的最大颜色数"，所以 1520 主图通常是 256 色 PNG（400KB 上下），肉眼几乎看不出差别。

**必须用渲染脚本出图，不要重写 HTML，也不要用 AI 生图**——中文生图会糊字，手写 HTML 会丢掉已经调好的立体与阴影参数。版式已经逐项验收过，任何"我觉得更好看"的改动都会破坏与历史图片的一致性。

## 触发场景

- 用户给一张新书封面，要求"按之前那套效果做一张"「生成主图」「网店上架图」
- 用户要求换书脊颜色、改文案、调字号等局部修改
- 用户一次性给多本书的封面，需要批量出图（循环调用脚本即可）

## 生成流程

一条命令完成。脚本自动处理三件原本需要手工判断的事：书脊配色、字号、比例校验。

```bash
python <skill>/scripts/make_poster.py \
  --cover 封面.jpg \
  --author 唐毅民 --note 编 \
  --title 低音提琴 --subtitle 考级曲集 \
  --spine 低音提琴考级曲集 \
  --out 输出目录/低音提琴考级曲集_电商主图.png
```

- `--out` 写出 1520×1520，同目录自动另存 `<同名>_760.png`
- `--max-size 1.0` 单张体积上限（MB），默认 1.0；传 `0` 关闭限制，恢复无损大图
- 脚本回吐 JSON：`font_main`、`spine_base_color`、`spine_text_color`、`bytes`/`encode`、`bytes_760`/`encode_760`、`warnings`
- 默认文案「官方正版 / 出版社仓库直发 / 官方自营店铺」，用户没提就别改
- `--spine` 省略时取 `--title + --subtitle` 拼接

脚本自动生成的三项：

| 项 | 规则 |
|---|---|
| 书脊渐变 | 取封面中位主色，按 0.32 / 0.50 / 0.78 / 1.00 / 0.42 五档明度生成，与封面天然协调，不必手工配色 |
| 书脊文字色 | 书脊中段亮度 > 150 用深色字，否则用 `#f8eee2` 浅色字 |
| 主字号 | 在最长一行 ≤ 380px 前提下取最大，上限 52px，下限 24px；作者后缀为 0.58 倍 |
| 输出体积 | 单张 ≤ `--max-size`（默认 1MB）：先无损，超限则按 256→16 色逐档量化，取塞得下的最大颜色数 |

## 硬参数（不要改）

这些数值是逐轮验收定下来的，改动即破坏一致性。

```
画布 760×760，device-scale-factor=2 → 1520×1520
封面画框 410×584（比例 0.702，封面照片需接近此比例）
书本 rotateY(24deg)，perspective 1850px / origin 54% 44%
书本厚度 46px，书脊与书页各宽 46px
文案区 left 363 / top 40 / width 364 / height 566，flex space-between 铺满
四组文字同字号、同一中轴居中
文字左端允许压到封面，最长行 ≤ 380px
底部黑条 760×78，bottom 22px
黑条内：白色 logo 块 372×72（左，占一半）+ 口号「官方自营店铺」（右，占一半）
单张输出 ≤ 1MB（--max-size 可调，默认 1.0）
```

## 出图后必须自检

渲染成功不等于结果可用。用看图工具逐条确认：

1. 右侧四行右端未超出画布，左端压图部分清晰可读
2. 书脊与封面接缝处没有白色缝隙
3. 书顶边水平，没有被裁掉一角
4. 底部黑条下方有柔和投影，不是平贴
5. logo 白块里英文 `PRESS` 末尾的 S 完整、没有黑边框
6. 书名没有被封面照片自带的反光/裁剪吃掉
7. 两个文件的字节数都 ≤ 1MB，且背景渐变区没有明显色带/颗粒（量化过度的信号）

任一项不通过，按下面口径修，不要重新设计版式。

## 常见修改诉求的处理口径

| 用户说 | 做法 |
|---|---|
| 「字再大一点」 | `--font-size` 显式指定，但先算宽度：CJK 按 1.0em、其他按 0.55em，加字距，总和 ≤ 380px 才安全 |
| 「书脊颜色不对」 | 脚本按封面主色自动生成，一般不用改；必须指定时复制模板改 `__SPINE_GRAD__` 处的 CSS 后走 `--template` |
| 「书的立体感不够」 | 只调 `.spine`/`.pages` 宽度（当前 46px）与 `.front` 的 `translateZ`（当前 23px），两处必须同步改，否则接缝露白缝 |
| 「黑条阴影太重/太轻」 | 调 `.bar` 的三层 `box-shadow` 不透明度，不动偏移距离（4/10/18px 是实测样书值） |
| 「要竖版 800×1000」 | 改画布尺寸后所有绝对定位都要重算，属于新排版，需另行验收，不要指望脚本自适应 |
| 「logo 被裁了」 | 重裁 logo 时把判定阈值放宽到 210（浅灰抗锯齿像素也要算），再向外留 8px 纯白 |
| 「图超过 1MB 传不上去」 | 默认已经压到 1MB 内；先看 JSON 的 `bytes` 是否真的超了，再确认 `--max-size` 没被改成 0 或调大。真要更小就传 `--max-size 0.6`，脚本会继续降色，别去改画布尺寸 |

## 已知硬约束

- **此视角看不到真实书页侧面**：书脊朝左、观察者在左，物理上看不到右侧书页。`.front` 上那两条 `5px/8px 0 0` 色带是模拟厚度感的假色带。要做到真实必须改视角，但那样书脊就看不见了。
- **不要给 `.book` 加 `rotateX`**：会让书顶边倾斜、书脊与封面顶部错位。
- **`.pages` 不要加 `translateZ`**：`rotateY` 正角度下右侧面朝后，加了会被封面完全遮住。
- **`.spine` 必须 `translateZ(半本书厚) rotateY(-90deg)`**：Z 上不对齐就会露白缝。
- **`background-clip:text` + `color:transparent` 的元素不能用大半径多层 `text-shadow`**：阴影会从笔画内部透出来，字发白起雾。只能用 `filter: drop-shadow()`。
- **封面比例偏离 0.702 超过 6%**：`background:cover` 会裁边，脚本会给出 warning，须人工确认书名没被裁掉。
- 封面照片自带的反光/光斑会原样保留，不是渲染问题；要"干净"商品图需索要无拍摄反光的封面设计稿。
- **PNG 只有两个档位，凑不出"正好 1MB"**：1520×1520 的 24 位无损约 1.3MB，256 色调色板约 400KB，中间没有可调旋钮。所以规范只承诺"≤ 1MB"，不承诺"= 1MB"。若要 700KB~900KB 的中间值只能换 JPEG，但 JPEG 会让深色字边缘产生振铃、发毛，不建议。
- **量化后不要再叠加重压缩**：调色板 PNG 再转一次格式会二次丢色，`--max-size` 已经是唯一入口。
